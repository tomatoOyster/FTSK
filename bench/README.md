# FTSK-4 v1 数字发射谱与接收预算

## 复现

在项目根目录执行以下命令。脚本通过 Python 的 zipimport 从本次发布压缩包加载帧编解码、插值、抽取和接收代码，各 JSON 含源码包 SHA-256、系统、Python 和 NumPy 版本。所有采样均在内存中生成，无射频发射。

```powershell
python bench/measure.py spectral --n 512
python bench/measure.py channel --n 96
python bench/measure.py timing
```

## 实际插值波形

512 个随机有效载荷，固定 PCG64 种子 481516。每帧独立地产生完整的包头、数据、前后各 256 个基带零样点；8 倍插值调用 v1 多相 Kaiser FIR，并对整包峰值执行与 SDR 命令相同的 0.8 归一化。按包对完整突发作矩形窗 FFT（包含滤波尾巴），将各包功率谱相加；以累计功率的 0.5% 和 99.5% 分位之差作为 OBW99。基带 FFT 为 8192 点，设备侧 FFT 为 65536 点，频点间距均为 15.625 Hz。

| 测量面 | OBW99 范围 / kHz | 宽度 / kHz | 有效包内 PAPR 中位数 / dB | 有效包内峰均比最大值 / dB |
|---|---:|---:|---:|---:|
| 128 kS/s 插值前 | −61.578 至 +61.547 | 123.125 | 0 | 0 |
| 1.024 MS/s 设备数字输入 | −61.297 至 +61.266 | 122.563 | 4.206 | 4.235 |

插值后的 PAPR 在扣除 32 个基带点的群延迟后，使用完整 35 ms 有效包的峰值与均方计算。若计入前后静默和滤波尾部，整次发射缓冲区为 40,448 个设备采样，持续 39.5 ms，PAPR 中位数为 4.731 dB，最大 4.760 dB。插值后有 0.03557% 的数字能量落在 ±64 kHz 之外。基带数字谱只定义于一个 128 kHz 周期内；前述带宽指复基带双边、等尾带宽。数字突发加权、硬件 DAC 重建、模拟滤波、功放线性度和 RBW 设置都会影响仪器上的读数。

## 载波误差和接收保护带

v1 的设备端模型先对插值后的 1.024 MS/s 波形施加载频偏移，然后用真实接收 FIR 抽取至 128 kS/s，最后才搜索并校正 CFO。漂移测试按设备时钟上的线性插值调整采样时标。纯载频偏移与采样时钟误差可独立设置。以 915 MHz 为例，两端相对 5、10、20 ppm 分别意味着 4.575、9.15、18.3 kHz；最后一种也可能来自两台各 ±10 ppm 的晶振朝相反方向偏移。±6 kHz 捕获范围在 915 MHz 仅相当于相对 ±6.56 ppm。

每个条件使用 96 次独立噪声和随机到达时刻（设备采样精度），校验收到的整段 32 字节。实验逐条件复用种子 481517。对照组采用整数基带定时，直接在 128 kS/s 端加 CFO 和同一条抽取过的设备噪声；设备组含滤波、分数采样定时以及带边损失。表中差异包含这些因素，不能单凭此表把所有差值归因于 FIR。SNR 是抽取前活动信号参考功率与抽取后噪声功率之比，按每组去除包级幅度归一化的影响，噪声方差按真实 FIR 的能量校准。每帧重新初始化接收机，测试限于独立单包。零失败的 96 次测试仍容许约 3.1% 的单侧 95% 误包率上界。

| 载荷、SNR | CFO / Hz | 直接基带成功数 / 96 | 设备链路成功数 / 96 |
|---|---:|---:|---:|
| 随机，−6 dB | 0 | 95 | 92 |
| 随机，−6 dB | +4000 | 93 | 83 |
| 随机，−6 dB | +5850 | 89 | 78 |
| 随机，−6 dB | +6000 | 89 | 80 |
| 随机，−6 dB | −6000 | 92 | 58 |
| 全零，−3 dB | −6000 | 96 | 0 |
| 全零，+15 dB | −6000 | 96 | 96 |
| 随机，−3 dB，相对 5 ppm | +4575 | 96 | 93 |
| 随机，+15 dB，相对 10 / 20 ppm | +9150 / +18300 | 均为 0 | 均为 0 |

全零数据使很多时段持续占用 −60 kHz。−6 kHz 偏移后，该频点到达 −66 kHz，位于 128 kS/s 抽取器的过渡带。接收 FIR 在 60、64、66 kHz 的幅度响应分别为 −0.046、−6.021、−18.099 dB。靠后级纠偏无法恢复已被前级削弱的频点。随机包也出现明显退化。−6000 Hz、−6 dB 的 96 个配对样本中，有 35 个只在对照组收到，1 个只在设备组收到。

## 抽取前校频的配对复测

运行 `python bench/correction.py` 可对当前工作树的宽带实现复测，结果中的 SHA-256 标明实际测量的源码。三种接收器逐次使用完全相同的设备 IQ。载荷全零，−3 dB，采样时钟误差为零，每组 24 个随机初相、到达时刻和独立噪声实现。

| CFO / Hz | 窄带接收 | 抽取前用已知 CFO 精确混频 | 四路盲搜 ±20 kHz |
|---|---:|---:|---:|
| −6000 | 0/24 | 24/24 | 24/24 |
| +6000 | 0/24 | 24/24 | 24/24 |
| +18300 | 0/24 | 24/24 | 23/24 |

已知频偏一栏直接使用测试信道的设定值。盲搜一栏仅获得最大搜索范围，抽取前分别按 −15、−5、+5、+15 kHz 混频，各支路自行估计残差。三组均无重复包输出。24 次试验适于复核这个反例和修复路径，24/24 的单侧 95% 误包率上限仍约为 11.7%。

## v1 实时预算

Intel Core i9-12900H、Windows 11、Python 3.12.14、NumPy 2.3.5。每次投喂 8 ms IQ，设备侧 8192 点、基带侧 1024 点。每个工况预热 1 次，计量独立 7 次，每次 1 秒输入；不计数据生成和接收机初始化。p99 为每轮 125 个块的 99 分位，表中取七轮中位数。

| v1 计算段 | 采样吞吐量 / kS/s | 实时倍率 | 每秒 IQ 的进程 CPU 秒 | 块耗时 p99 / ms |
|---|---:|---:|---:|---:|
| 128 kS/s 白噪声持续监听 | 150.9 | 1.18× | 0.828 | 10.09 |
| 128 kS/s 首尾相连的数据包 | 147.4 | 1.15× | 0.859 | 10.79 |
| 1.024 MS/s 单独抽取 | 793.5 | 0.775× | 1.266 | 12.54 |
| 1.024 MS/s 抽取及连续噪声监听 | 409.7 | 0.400× | 2.469 | 26.24 |

原版 1.024 MS/s 组合处理每秒 IQ 需要约 2.50 秒墙钟时间。单独的 128 kS/s 监听在该机器上平均有余量，但单个 8 ms 块的 p99 已超过 8 ms，实时使用还依赖缓冲深度。计时包含 Python 和 NumPy 内存分配，受系统负载、温度、电源模式与线程调度影响，未计驱动 I/O。这些数据针对上方 SHA 固定的 v1 代码，后续优化需重新计时。
